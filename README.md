# WB-shop

Интернет-магазин, в котором пользователи могут просматривать товары, добавлять их в корзину и делать заказы.

Проект представляет собой **MVP бэкенда с REST API** в качестве **тестового задания от *«Школы стажеров WB-Tech»***.

## Стек технологий

Backend: **Python**, **Django 5.2**, **Django REST Framework 3.15**, **PostgreSQL**, **Simple JWT**, **Pytest**.

Deployment: **Docker**.

Style-check: **Ruff**.

API documentation: **drf-spectacular (Swagger / OpenAPI)**.


## Возможности

### Пользователи

Пользователи могут:

* регистрироваться и авторизовываться;
* получать и обновлять данные своего профиля;
* пополнять свой баланс;

Для аутентификации используется **JWT** с типом авторизации `Bearer`.

Токены имеют ограниченный срок действия. Refresh-токены **ротируются при обновлении**, а использованный refresh-токен добавляется в blacklist.

### Товары

Пользователи могут:

* просматривать список товаров;
* просматривать информацию о конкретном товаре;
* добавлять товары в корзину;
* сортировать товары по **цене** и **количеству на складе**.

Для товаров реализовано **soft-delete**: товар не удаляется физически из базы данных, а получает соответствующий статус и дату удаления. Такие товары не отображаются в каталоге обычных пользователей.

Администратор может:

* создавать товары;
* изменять товары;
* удалять товары;
* восстанавливать удалённые товары;
* просматривать удалённые товары;
* управлять количеством товара на складе.

### Корзина

Авторизованный пользователь имеет собственную корзину покупок.

Пользователь может:

* просматривать содержимое корзины;
* добавлять товары в корзину;
* изменять количество товара в корзине;
* удалять товар из корзины.

При добавлении уже существующего товара в корзину его количество увеличивается на один.

Товары, отсутствующие на складе или удалённые из магазина, нельзя добавить в корзину.

### Заказы

Авторизованный пользователь может оформить заказ на основе содержимого своей корзины.

При создании заказа:

* проверяется наличие товаров на складе;
* проверяется, что товары не были удалены;
* проверяется наличие необходимой суммы на балансе;
* рассчитывается итоговая стоимость заказа;
* количество товаров на складе уменьшается;
* средства списываются с баланса пользователя;
* содержимое корзины очищается;
* создаются позиции заказа.

В заказе сохраняется **снимок товара на момент покупки**: название, цена, количество и итоговая стоимость позиции. Это позволяет сохранить корректную информацию о заказе даже после последующего изменения товара.

Пользователь может:

* просматривать свои заказы;
* получать информацию о конкретном заказе;
* сортировать по **дате создания** и **итоговой стоимости**;
* фильтровать по **статусу**.

Администратор может:

* просматривать заказы пользователей;
* просматривать дополнительные данные по заказам;
* изменять статус заказа.

### Права доступа

В API реализовано разграничение прав доступа.

**Анонимный пользователь** может просматривать товары и взаимодействовать с операциями аутентификации.

**Обычный авторизованный пользователь** работает со своими данными, корзиной и заказами.

**Администратор** получает дополнительные возможности для управления товарами и заказами.


### Логирование

В проекте настроено логирование Django-приложения.

Логи:

* выводятся в **консоль**;
* сохраняются в файл `logs/django.log`;
* используют формат, содержащий дату, уровень логирования, имя логгера и сообщение;
* записываются с уровнем **INFO**.

Для файлового логирования используется `RotatingFileHandler`, который автоматически создаёт резервные файлы при достижении установленного размера.

При создании заказа также записывается информационное сообщение с идентификатором заказа и пользователя.

## Развёртывание

Для локального запуска потребуются: **Python**, **Docker** и **Git**.

### 1. Клонирование репозитория

```bash
git clone https://github.com/TimurBikmaev/wb_shop.git
cd wb_shop  # Перейдите в директорию проекта
```

### 2. Запуск Docker Compose (запустит Django-проект и PostgreSQL)

```bash
docker compose up -d
```

### 3. Применение миграций

```bash
docker compose exec backend python manage.py migrate
```

### 4. Создание администратора

```bash
docker compose exec backend python manage.py createsuperuser
```

Админка доступна по адресу: http://localhost:8000/admin/

### 5. Создание корзины покупок для администратора

```bash
docker compose exec backend python manage.py shell
from django.contrib.auth import get_user_model
from product.models import Cart
User = get_user_model()
user = User.objects.get(email="<admin_email>")
Cart.objects.create(user=user)
exit
```
